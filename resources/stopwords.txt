# English stopwords. Used by the prose heuristic and by Stage 3 (YAKE).
#
# Lines beginning with # are ignored; entries are whitespace-separated, so a line here is
# a run of words rather than one entry.
#
# Source: NLTK's English stopword corpus, which originates in the Snowball lists. See
# NOTICE for attribution. Two edits are applied by the regeneration script, which prints
# both so the diff is reviewable:
#
#   DROPPED — the stems and clitics of negated contractions (`didn`, `isn`, `wasn`, `ve`,
#   `ll`, `s`, `t`, `ma`). They exist in NLTK's list only because its tokeniser splits
#   `didn't` into `did` + `n't`; ours keeps it whole, so they can never match. One of
#   them, `won`, is a real English verb that would otherwise be suppressed.
#
#   ADDED — the modals NLTK omits (may, might, must, shall, should, would, could, cannot,
#   ought) and the prepositions across, among, upon, within, without. Without the modals
#   YAKE admits "may require calibration" as a candidate phrase headed by a function word,
#   and the prose gate undercounts function-word density in formal register.
#
# It is deliberately NOT NLTK's list verbatim, and deliberately not the `stop-words`
# crate. Both are built for a tokeniser that splits `didn't` into `did` + `n't`, so a
# quarter of NLTK's entries are fragments (`didn`, `isn`, `wasn`, `ve`, `ll`, `s`, `t`)
# that our tokeniser can never produce — and one of them, `won`, is a real English verb.
# A stopword list has to match the tokeniser that consumes it. `stopword_entries_are_
# tokens_our_tokeniser_can_actually_produce` in src/resources.rs pins that agreement.
#
# Regenerate with scripts/fetch_stopwords.sh. Order is not significant.
